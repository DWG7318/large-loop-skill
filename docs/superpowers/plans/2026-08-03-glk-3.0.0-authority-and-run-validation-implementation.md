# GLK 3.0.0 Authority and Run Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task in the existing `feature/glk-3.0.0` worktree. Keep every RED result before its matching implementation commit.

**Goal:** Replace GLK 2.4's self-asserted, mixed-authority Run records with a breaking 3.0 contract bundle, immutable Run package loader, and executable ten-layer cross-artifact validator while preserving the six-role no-READY GO DAG and its maximal-safe activation and causal-recovery semantics.

**Architecture:** Formal evidence is an append-only ledger of independently issued artifacts. A loader scans the complete package and validates its versioned index chain; a validator recomputes authority, lineage, CELL closure, DAG, admissions, D3, and Owner gates. GLK defines four provenance-adapter operations but never implements credentials, sessions, Broker, replay, checkpoint, or Agent runtime.

**Tech Stack:** Python 3.12+, dataclasses, `typing.Protocol`, pathlib, hashlib, JSON Schema Draft 2020-12, YAML, pytest.
