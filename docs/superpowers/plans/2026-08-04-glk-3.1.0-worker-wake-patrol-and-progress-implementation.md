# GLK 3.1.0 Worker Wake, Patrol, Progress, and Capacity Implementation Plan

> Execute this plan inline in the existing `feature/glk-3.1.0-worker-wake-patrol` worktree. Do not create Codex tasks, subagents, hidden/background Agents, or remote actions. Apply strongest `$st`, the accepted GLK 3.0 design plus the GLK 3.1 design, `executing-plans`, TDD, and verification-before-completion.

**Goal:** Release a locally committed GLK 3.1.0 contract that adds Worker-only four-level Checker wake, a unique non-authoritative Run patrol, layered receipt-derived progress, and device/cumulative-load-aware CELL capacity gating without changing the six technical roles or D0-D3 authority model.

**Architecture:** Four small pure-Python control modules (`worker_wake`, `run_patrol`, `progress_reporting`, `cell_capacity`) consume immutable caller-supplied facts through injected interfaces. Existing `preflight`, `run_control`, `run_package`, and `run_validation` integrate them. Schemas and templates make the control records machine-checkable. External trusted environments continue to own threads, heartbeats, clocks, device observations, credentials, sessions, and Runtime behavior.

**Base:** GLK 3.0.0 commit `bbd540311cb231472ef1a132ef5d174e5623afa0`; design commit `0b04e867bdc64b19cd14cdc00f2e403049819dd1`.

**Normative design:** `docs/superpowers/specs/2026-08-04-glk-3.1.0-worker-wake-patrol-and-progress-design.md`.

**Global invariants:** Exactly six technical roles; fresh Supervisor; no `READY`; maximal-safe `WAITING_GO`/`ACTIVE_GO`; patrol is not a seventh role; Worker ladder is not a generic message bus; no scheduler, Runtime, Broker, replay, checkpoint, credential, session, or device collector; production checks do not rely on `assert`.
